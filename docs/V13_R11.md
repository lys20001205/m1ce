# V13 R11: return the view after choosing a speed

An independent normal-input session at 844×390 completed a freight run, loaded two boxes, bought a handgun, cashed out 3300 Bank, purchased boots/hull/kit and began another run. It used the release entry, ordinary controls and read-only snapshots; no game-state or save fixtures. Software-rendered browser play is not human or physical-phone testing.

At 95.513 seconds the player selected CRUISE after unloading. The ENGINE CONSOLE remained over the character and central combat area in subsequent screenshots around 155 and 215 seconds. Selecting a speed did not dismiss the panel; pressing F again or leaving console range was required. A later run reproduced the same obstruction. The pass selects this single issue, rather than adding unrelated gameplay changes.

R11 closes the speed panel only when the existing `setSpeed` operation succeeds, including selecting the already active speed. Rejected direction changes retain the panel and existing reason message. No speed, braking, battery, combat, movement, model, economy or save rule changes. F still reopens the console; walking out of range retains its existing behavior.

The existing real-browser route suite selects CRUISE and checks that the world is exposed, reopens the console and attempts an illegal reverse while moving, checks that mode/panel are retained, then selects FAST and checks dismissal. Existing gameplay and performance gates remain. Independent affected-input/visual QA and complete exact-code CI are required before release.

Cache investigation and deployment evidence changes are documented separately in [CACHE_UPGRADE.md](CACHE_UPGRADE.md). Fresh startup, stale first navigation and ordinary-refresh recovery remain distinct results; previous failed automatic migration is not reclassified as success.
